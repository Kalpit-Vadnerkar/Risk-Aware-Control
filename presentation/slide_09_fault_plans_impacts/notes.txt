These two plot types (fault_plan.py, fault_impact.py) come from the existing experiments/lib/plotting.py shared module, built this session by consolidating three previously-separate, cross-importing scripts (plot_routes.py, plot_fault_plan.py, plot_fault_impact.py) into one reusable set of map-loading/zone-drawing/outcome-styling primitives — the same module plot_predictions.py (slide 10) and the signal-quality tables (slide 11) build on.

Good concrete example to have ready if asked "how do you know the fault actually worked": the whole project's philosophy (see CLAUDE.md's "before trusting newly-collected experiment data" section) is not to trust result.json's status field alone — every campaign gets checked with a chain of verification scripts (analyse_experiments.py, analyze_mrm_diagnostics.py, compare_fault_vs_nominal.py, verify_imu_zone_arming.py / verify_tl_zone_arming.py) before being used for anything downstream. This slide's plot is the visual version of that discipline.
